# Gotchas — macOS Ecosystem

General technical gotchas, traps, and workarounds for macOS system development (Cocoa, AppKit, Metal, Carbon, Darwin PTY, SkyLight).

---

## [mac-01] 2026-08-28 Raylib + Cocoa Window Transparency & Layer Ordering [Status: Verified] [Agent: manual]
**Symptom**: Vibrant blur composites on top of OpenGL, completely occluding all rendered graphics in transparent window setups.
**Cause**: Adding `NSVisualEffectView` as a subview of GLFW's view causes Cocoa to composite vibrancy on top of OpenGL.
**Workaround**: For transparent window vibrancy, `NSWindow` must have `opaque = NO`, `backgroundColor = clearColor`, and `styleMask = NSWindowStyleMaskBorderless | NSWindowStyleMaskFullSizeContentView`. `NSVisualEffectView` must be set as the window's `contentView`, with GLFW's OpenGL rendering view added as a subview *inside* `NSVisualEffectView`. Raylib must clear the frame with `rl.ClearBackground({0, 0, 0, 0})` so the underlying vibrancy shines through.
**Anchors**: `NSVisualEffectView`, `NSWindow`, `rl.ClearBackground`.

## [mac-02] 2026-08-28 Event Loop Starvation when Window is Hidden [Status: Verified] [Agent: manual]
**Symptom**: Carbon hotkey events (`RegisterEventHotKey`) are not dispatched when window is hidden (e.g. auto-hide on blur).
**Cause**: When the window is hidden, rendering stops and `rl.EndDrawing()` is not called. Without continuous event polling, macOS will not dispatch Carbon events.
**Workaround**: `rl.PollInputEvents()` and platform poll events must be called unconditionally on every loop iteration, paired with a small sleep (16ms) when hidden to prevent high CPU usage while maintaining responsive hotkey toggles.
**Anchors**: `RegisterEventHotKey`, `rl.PollInputEvents()`.

## [mac-03] 2026-08-28 Cocoa Borderless Window Key Focus & Event Polling [Status: Verified] [Agent: manual]
**Symptom**: Borderless `NSWindow` cannot receive keyboard input focus or first responder status.
**Cause**: Windows with `NSWindowStyleMaskBorderless` in Cocoa return `NO` for `canBecomeKeyWindow` and `canBecomeMainWindow` by default.
**Workaround**: Subclass `NSWindow` (or swizzle) returning `YES` for `canBecomeKeyWindow` and `canBecomeMainWindow` so `[window makeFirstResponder:subview]` and `[window makeKeyAndOrderFront:nil]` route keyboard focus properly. When visible, do not allow custom platform poll loops to steal NSApp events from GLFW's event pump.
**Anchors**: `NSWindow.canBecomeKeyWindow`, `NSWindowStyleMaskBorderless`.

## [mac-04] 2026-08-29 NSPasteboard Privacy & Concealed Password Filtering [Status: Verified] [Agent: manual]
**Symptom**: Sensitive passwords, TOTP codes, and credentials from password managers (1Password, Bitwarden, KeePassXC, Apple Keychain) leak into clipboard history.
**Cause**: `NSPasteboard.general` receives all copy events by default, including transient and concealed data.
**Workaround**: Inspect `NSPasteboard.general.types` on every read and skip recording if types contain any of: `org.nspasteboard.ConcealedType`, `org.nspasteboard.AutoGeneratedType`, `com.agilebits.onepassword`, or `org.nspasteboard.TransientType`.
**Anchors**: `NSPasteboard.general.types`, `org.nspasteboard.ConcealedType`.

## [mac-05] 2026-08-30 Developer Toolchain Path Discrepancy & Test Sandbox Hermeticity [Status: Verified] [Agent: manual]
**Symptom**: CI builds fail finding frameworks, or unit tests crash accessing hardcoded user paths.
**Cause**: Local macOS setups frequently point `xcode-select -p` to `/Library/Developer/CommandLineTools`, whereas GitHub Actions `macos-15` runners point to `/Applications/Xcode.app/Contents/Developer`.
**Workaround**: Dynamically discover toolchain paths: `DEVELOPER_DIR ?= $(shell xcode-select -p 2>/dev/null || echo /Library/Developer/CommandLineTools)` and pass dynamic `-F$(DEVELOPER_DIR)/Library/Developer/Frameworks`. Never hardcode user paths; isolate test state into ephemeral UUID-named `FileManager.default.temporaryDirectory` folders with `defer` cleanup.
**Anchors**: `xcode-select -p`, `FileManager.default.temporaryDirectory`.

## [mac-06] 2026-08-31 macOS System Permission / TCC Dialogs and Auto-Hide on Blur [Status: Verified] [Agent: manual]
**Symptom**: Floating HUD window dismisses immediately when an OS security/permission prompt (TCC, SecurityAgent) appears on its behalf.
**Cause**: Out-of-process system modals (`CoreServicesUIAgent`, `SecurityAgent`, `UserNotificationCenter`) steal key window focus (`NSWindow.didResignKeyNotification`).
**Workaround**: Defer resign check to next runloop turn via `DispatchQueue.main.async` and inspect `NSWorkspace.shared.frontmostApplication`. If frontmost bundle starts with `com.apple.coreservices*`, `com.apple.SecurityAgent`, `com.apple.UserNotificationCenter`, or the host app itself, suppress window dismissal and restore key status via `NSApplication.didBecomeActiveNotification`.
**Anchors**: `NSWorkspace.shared.frontmostApplication`, `windowDidResignKey`.

## [mac-07] 2026-08-31 Pasteboard Polling, RunLoop Interrupts & Timer Coalescing [Status: Verified] [Agent: manual]
**Symptom**: Idle app consumes 1.5% to 2.0% CPU just waiting for clipboard updates in the background.
**Cause**: Querying `NSPasteboard.general.changeCount` triggers a synchronous Mach IPC (`mach_msg`) roundtrip to `pbs` / `pasteboardd`. Scheduling repeating `Timer` on `RunLoop.main` without tolerance wakes CPU cores 120 times/min, preventing deep C-state processor sleep.
**Workaround**: Use a `DispatchSourceTimer` on a serial `.utility` QoS background queue with leeway (500ms) and an interval of 1.0s. This enables macOS timer coalescing, dropping idle CPU consumption to < 0.1%.
**Anchors**: `DispatchSourceTimer`, `NSPasteboard.general.changeCount`.

## [mac-08] 2026-09-02 Duplicate Dynamic Bundle Loading & Objective-C Class Symbol Collisions [Status: Verified] [Agent: manual]
**Symptom**: Immediate `Bus error: 10` (SIGBUS) or duplicate class warnings in Objective-C runtime when loading dynamic plugin dylibs.
**Cause**: Dynamically loading two bundle copies of the same Swift Mach-O dylib into the same process causes Mach-O dyld to register duplicate Swift type metadata, corrupting internal type lookup caches.
**Workaround**: Deduplicate bundles by `manifest.id` during discovery and reindexing. Guard in plugin host by returning existing loaded instances if `manifest.id` is already registered. Avoid `@objc(ExplicitName)` on dynamic bundle plugin classes; resolve classes via bundle-scoped APIs (`bundle.classNamed`, `bundle.principalClass`).
**Anchors**: `bundle.classNamed`, `manifest.id`, `SIGBUS`.

## [mac-09] 2026-09-03 NSAppleScript Thread-Safety & SkyLight Queue Assertion Crash [Status: Verified] [Agent: manual]
**Symptom**: Immediate process crash with `SIGTRAP: 5` inside `CGSDatagramReadStream::dispatchMainQueueDatagrams`.
**Cause**: Invoking `NSAppleScript.executeAndReturnError` from a background cooperative thread sends AppleEvents via Carbon/HIToolbox. During delivery, HIToolbox pumps the current thread's CFRunLoop, waking SkyLight datagram dispatch which asserts `dispatch_assert_queue(dispatch_get_main_queue())`.
**Workaround**: Always marshal AppleScript execution to the main thread via `Thread.isMainThread` or `@MainActor`. Automated test runs must detect test environment and mock out destructive system automation.
**Anchors**: `NSAppleScript.executeAndReturnError`, `dispatch_assert_queue(dispatch_get_main_queue())`.
