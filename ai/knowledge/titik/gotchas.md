# Gotchas & Platform Notes

1. **Raylib + Cocoa Window Transparency & Layer Ordering**:
   - `NSWindow` must have `opaque = NO`, `backgroundColor = clearColor`, and `styleMask = NSWindowStyleMaskBorderless | NSWindowStyleMaskFullSizeContentView`.
   - `NSVisualEffectView` must be set as the window's `contentView`, with GLFW's OpenGL rendering view added as a subview *inside* `NSVisualEffectView`. Adding `NSVisualEffectView` as a subview of GLFW's view causes Cocoa to composite the vibrancy effect on top of OpenGL, occluding all rendered graphics.
   - Raylib must clear the frame with `rl.ClearBackground({0, 0, 0, 0})` so the underlying Cocoa visual effect view shines through.

2. **Event Loop Starvation when Window is Hidden**:
   - When the window is hidden (e.g. auto-hide on blur), `rl.EndDrawing()` is not called. Without continuous event polling, macOS will not dispatch Carbon hotkey events (`RegisterEventHotKey`).
   - `rl.PollInputEvents()` and `titik_platform_poll_events()` must be called unconditionally on every loop iteration, paired with a small sleep (16ms) when hidden to prevent high CPU usage while maintaining responsive hotkey toggles.

3. **Raylib Font Rendering & Unicode Glyphs**:
   - Raylib's `GetFontDefault()` is a 10px ASCII bitmap font that cannot render Unicode symbols (`⌘`, `⚡`, `↵`, `✦`) or scale cleanly.
   - TrueType fonts (e.g. `/System/Library/Fonts/SFNS.ttf` or `/System/Library/Fonts/Geneva.ttf`) must be loaded using `raylib.LoadFontEx` with explicit Unicode codepoint slices and bilinear texture filtering.

4. **Odin Core OS & Linker on macOS**:
   - When compiling or testing packages importing `src/platform`, always supply `-extra-linker-flags:"-framework Cocoa -framework Carbon -framework OpenGL bin/macos_bridge.o"`.
   - In Odin, `raylib.Color` is a distinct `[4]u8` fixed array; cast byte arrays directly via `raylib.Color(b)`.

5. **macOS Cocoa Borderless Window Key Focus & Event Polling**:
   - Borderless `NSWindowStyleMaskBorderless` windows in Cocoa return `NO` for `canBecomeKeyWindow` and `canBecomeMainWindow` by default. They must be subclassed/swizzled (e.g. `TitikWindow : NSWindow`) returning `YES` so `[window makeFirstResponder:glfwView]` and `[window makeKeyAndOrderFront:nil]` route keyboard focus to GLFW.
   - When the window is visible, `rl.PollInputEvents()` (`glfwPollEvents()`) pumps NSApp events. Custom platform poll loops must not dequeue and steal events while visible.

6. **SwiftUI Structural Identity & ScrollView State Retention**:
   - Placing `ScrollView` / `ResultsListView` inside conditional `if/else` branches (`if hasRichPreview`) causes SwiftUI to assign different structural identities to the branches, destroying the `ScrollView` and resetting scroll position back to top when switching between items with and without previews.
   - To preserve scroll position, maintain a single persistent `ResultsListView` in the view hierarchy and animate width dynamically (`geo.size.width * 0.55` vs `geo.size.width`) while conditionally showing/hiding sibling preview panes with `.asymmetric` transitions.

7. **SwiftUI List Row Jumping from Dynamic Text Font Weights**:
   - Toggling font weights (e.g. `.semibold` when selected vs `.medium` when unselected) forces CoreText to re-measure glyph widths on every selection change, causing the text bounding box and row height to dynamically shift/jump.
   - Keep row layout metrics (font weight, padding, height) 100% static across selection states and decouple the selection indicator into an independent background plate layer (`RoundedRectangle` fill + stroke modulated via `.opacity`).

8. **SwiftUI High-Frequency Keyboard List Scrolling & Animation Queue Pileup**:
   - Wrapping `proxy.scrollTo` in `withAnimation` during keyboard navigation causes rapid key repeat events (30–60Hz) to spawn overlapping spring animations, overloading SwiftUI's render tree and causing severe rubber-banding lag and micro-jitters.
   - Use explicit `Transaction().disablesAnimations = true` with `withTransaction` for zero-latency, 120fps intermediate list tracking, and decouple boundary rubber bouncing into a separate bounded offset layer triggered exclusively at top/bottom limits.

9. **macOS NSPasteboard Privacy & Concealed Password Filtering**:
   - `NSPasteboard.general` includes transient passwords and secrets copied from 1Password, Bitwarden, KeePassXC, and Apple Keychain.
   - To prevent sensitive credential leaks, clipboard managers must check `NSPasteboard.general.types` and skip recording if types include `org.nspasteboard.ConcealedType`, `org.nspasteboard.AutoGeneratedType`, `com.agilebits.onepassword`, or `org.nspasteboard.TransientType`.

10. **Synchronous Media & Disk Decoding in SwiftUI View Rendering**:
    - Calling synchronous media extractors (e.g. `AVAssetImageGenerator.copyCGImage`, `PDFDocument.page.thumbnail`, or heavy `Data(contentsOf:)`) directly inside SwiftUI `body` blocks the `@MainActor` thread, causing perceptible UI hitches during rapid keyboard navigation.
    - Heavy previews must always be decoupled into background `.task(id: url)` jobs updating `@State` asynchronously while displaying lightweight skeleton placeholders.

11. **GitHub Actions `macos-14` runner missing Swift 6.0 / Xcode 16**:
    - `Package.swift` requires `// swift-tools-version: 6.0`, but `macos-14` runners only provide Swift 5.10.0 (Xcode 15 default).
    - `sudo xcode-select -s /Applications/Xcode_16.app/Contents/Developer || true` fails silently because Xcode 16 is not installed on `macos-14`, leaving the runner on the incompatible Swift 5.10.0 without any error signal.
    - **Fix**: Use `runs-on: macos-15`. The `macos-15` runner ships with Xcode 16.4 and Swift 6.x as default — no `xcode-select` step required.
    - Applies to both `.github/workflows/ci.yml` and `.github/workflows/release.yml`.

12. **Streaming AI Plugins vs Search Bar Real-Time Keystrokes**:
    - In `UIOrchestrator`, search queries update `@Published query` on every keystroke. Dispatching remote network requests (e.g. LLM streaming endpoints) immediately inside `handleSearchQuery` spams the API server with rapid cancellations on every keystroke, pollutes multi-turn chat history (`AISessionCoordinator`), and triggers false `cancelled` errors.
    - Keep search keystrokes decoupled from AI network calls by holding `pendingQuery` in the adapter and executing `submitQuery()` only on explicit Return / Enter keypress, prompt chip selection, or follow-up submission. Stream cancellations must be logged at `debug` level and handled gracefully.

13. **DuckDuckGo Scraping is Unofficial & Fragile (ask_ai WebSearchService)**:
    - Web results come from `html.duckduckgo.com/html/?q=` HTML scraping; images require a two-step flow: fetch the query page to extract the `vqd` token, then call `duckduckgo.com/i.js?...&vqd=<vqd>` for JSON image results.
    - Result hrefs may be `/l/?uddg=<percent-encoded>` redirect wrappers — the real URL must be decoded from `uddg`, not used raw.
    - These are unofficial endpoints with no SLA; DDG markup changes will silently break parsing. All failures are escaped (never thrown): search failure must degrade to ungrounded chat, never block a response. A stub hook (`setStubHandler`) exists for tests so E2E never hits the real network.

14. **`TitikPlugin` protocol witness vs default arguments (Swift)**:
    - Swift does not match an `init(context:)` protocol requirement to an `init(context:webSearchService:)` with a defaulted parameter — the witness fails to compile.
    - Fix pattern: keep the injectable designated init and add a `public convenience init(context:)` delegating to it. A designated init cannot delegate to another designated init in the same class.

15. **Developer Toolchain Path Discrepancy & Test Sandbox Hermeticity**:
    - Local macOS machines frequently have `xcode-select -p` pointing to `/Library/Developer/CommandLineTools`, whereas GitHub Actions `macos-15` runners point to `/Applications/Xcode.app/Contents/Developer`.
    - Hardcoding static paths like `/Library/Developer/CommandLineTools/...` in `Makefile` or `Package.swift` breaks in CI. Instead, use dynamic discovery: `DEVELOPER_DIR ?= $(shell xcode-select -p 2>/dev/null || echo /Library/Developer/CommandLineTools)` and pass dynamic `-F$(DEVELOPER_DIR)/Library/Developer/Frameworks`.
    - Never write tests that access live host paths (`~/.config/titik/` or query `~` directly). Always isolate test state into ephemeral UUID-named `FileManager.default.temporaryDirectory` folders with `defer` cleanups to prevent permission crashes across differing execution environments.

16. **Plugin View & Bang Routing Architecture (No Search Interception)**:
    - In Titik, typing `!<bang><space>` (e.g. `!shortcut `, `!zen `, `!open `) routes directly to the corresponding plugin's stream (`pluginHost.query(...)`).
    - `SearchEngine` must NEVER synthesize artificial static command description stubs (e.g. `List Shortcuts`) that intercept or block the streaming query from reaching the plugin.
    - The plugin dynamically produces and filters its items/canvas in `onQuery(...)`.
    - In `UIOrchestrator.executeSelected()`, only genuine bang suggestions (`item.id.hasPrefix("bang:")`) autocomplete/fill the query bar. All actionable plugin items must directly execute `item.action()`.

17. **Synchronous Semaphore Blocking on `@MainActor` Keystrokes**:
    - Invoking search methods that block on `DispatchSemaphore.wait(timeout:)` directly from `@Published var query` freezes the `@MainActor` runloop, creating severe input lag and frame drops upon initial typing.
    - Searches must always be decoupled into cooperative asynchronous tasks (`searchAsync`) using Swift Structured Concurrency (`withTaskGroup`), micro-debouncing (50ms), and checking `Task.isCancelled` at cancellation boundaries so outdated searches do not overwrite newer keystroke results.

18. **SearchItem Action Closure Recursion & Async Task Fork Bomb**:
    - When SearchItems are created for native plugins or built-ins (`titik.builtin.clipboard`, `titik.builtin.app`, etc.), their `action` closures must not blindly forward to a global dispatcher that falls back to re-searching the same query (`self.dispatch(query: payload)`).
    - Re-searching the payload returns the exact same item, whose action invokes the dispatcher again, triggering an exponential asynchronous fork bomb (`Task` spawning `Task`) that consumes 200%+ CPU, freezes the test runner, and outputs hundreds of thousands of log lines.
    - Always handle built-in plugin IDs explicitly in the dispatcher and log unhandled plugins as a warning rather than recursively re-dispatching.

19. **macOS System Permission / TCC Dialogs and Auto-Hide on Blur**:
    - Out-of-process system modals (e.g. `CoreServicesUIAgent` for TCC Downloads/Documents folder access, `SecurityAgent`) steal key window focus from borderless floating panels (`NSWindow.didResignKeyNotification`).
    - If `windowDidResignKey` calls `hideWindow()` unconditionally, the HUD vanishes immediately when an OS security prompt is triggered on its behalf, leaving the user with an orphaned permission dialog.
    - Defer the resign check to the next runloop turn via `DispatchQueue.main.async` and inspect `NSWorkspace.shared.frontmostApplication`. If frontmost is `com.apple.coreservices*`, `com.apple.SecurityAgent`, `com.apple.UserNotificationCenter`, or the host app itself, suppress window dismissal and restore key status via `NSApplication.didBecomeActiveNotification`.

20. **macOS Pasteboard Polling, RunLoop Interrupts & Timer Coalescing**:
    - Querying `NSPasteboard.general.changeCount` triggers a synchronous Mach IPC (`mach_msg`) roundtrip to the system pasteboard daemon (`pbs` / `pasteboardd`).
    - Scheduling a repeating `Timer` on `RunLoop.main` without tolerance (e.g. every 0.5s) wakes the GUI thread and low-power CPU cores 120 times/min, causing Activity Monitor to report ~1.5% to 2.0% idle CPU usage.
    - **Fix**: Use a `DispatchSourceTimer` on a serial `.utility` QoS background queue with leeway (e.g. 500ms) and an interval of 1.0s. This enables macOS timer coalescing and preserves deep C-state processor sleep, dropping idle CPU consumption to < 0.1%.

21. **Duplicate Dynamic Bundle Loading & Objective-C Class Symbol Collisions (`Bus error: 10`)**:
    - Dynamically loading two bundle copies of the same Swift Mach-O dylib into the same process (e.g. from both `~/.config/titik/plugins/` and app `builtInPlugInsURL`) causes Mach-O dyld to register duplicate Swift type metadata. This corrupts internal type lookup caches, causing an immediate `Bus error: 10` (SIGBUS).
    - If a reference plugin class (e.g. `ActivityMonitorPlugin`) is compiled into the main executable while also being packaged into an external bundle, marking the plugin with `@objc(ActivityMonitorPlugin)` triggers duplicate class registration warnings in the Objective-C runtime.
    - **Fix**:
      1. Deduplicate bundles by `manifest.id` during discovery and reindexing in `PluginManager`. Prioritize user extensions in `~/.config/titik/plugins/` and ignore duplicates in lower-priority search directories.
      2. Guard in `PluginHost.loadNativePluginBundle` by returning existing loaded instances if `manifest.id` is already registered.
      3. Avoid `@objc(ExplicitName)` on dynamic bundle plugin classes; resolve classes via bundle-scoped APIs (`bundle.classNamed`, `bundle.principalClass`).
